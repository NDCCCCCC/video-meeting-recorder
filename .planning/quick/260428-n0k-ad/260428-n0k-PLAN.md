<objective>
Persist AD domain controller configuration to the SQLite database so that settings saved through the admin API survive server restarts.

Purpose: Currently UpdateAuthConfig only updates the in-memory config struct. On server restart, all AD configuration (server address, bind DN, base DN, TLS settings, mode) reverts to values in config.yaml. This makes the admin settings UI misleading - changes appear saved but are lost on restart.

Output: A SystemSetting model, a ConfigService for DB-backed config persistence, and updated AdminHandler that saves/loads AD config from database.

**1. Create `internal/models/system_setting.go`** - A key-value model for persisting arbitrary system configuration:

```go
package models

// SystemSetting stores system configuration as key-value pairs.
// Each unique Key has one row. The Value stores JSON-encoded data.
// This is a general-purpose config persistence table.
type SystemSetting struct {
    ID    uint   `gorm:"primarykey" json:"id"`
    Key   string `gorm:"type:varchar(100);uniqueIndex;not null" json:"key"`
    Value string `gorm:"type:text;not null" json:"value"` // JSON-encoded
}
```

Use a simple flat struct WITHOUT the Base embedded struct (no soft-delete needed for settings - they are always overwritten, never deleted). The table name is `system_settings`.

Use well-defined key constants:
- `"auth.mode"` - stores the mode string ("local" or "ad")
- `"auth.ad"` - stores JSON of the entire ADAuthConfig (minus password)
- `"auth.ad.password"` - stores the encrypted AD bind password separately

**2. Create `internal/services/config_service.go`** - A service for loading/saving auth config from/to DB:

```go
package services

type ConfigService struct {
    db     *gorm.DB
    logger *zap.Logger
    cfg    *config.Config // live config reference for in-memory sync
}

func NewConfigService(db *gorm.DB, logger *zap.Logger, cfg *config.Config) *ConfigService
```

Methods:
- `LoadAuthConfig() error` - Called at startup. Reads `auth.mode`, `auth.ad`, `auth.ad.password` from DB. If DB rows exist, override the in-memory `cfg.Auth.Mode` and `cfg.Auth.AD.*` fields. If no rows exist (first start), keep YAML defaults. This is the critical startup hook.
- `SaveAuthConfig(mode string, adConfig *auth.ADAuthConfig) error` - Called from UpdateAuthConfig handler. Stores mode to `auth.mode`, AD config (minus password) as JSON to `auth.ad`, and password to `auth.ad.password`. Also updates the live `cfg` in-memory.

**Password security:** The AD bind password must be encrypted before storing in DB. Use the existing SM4 encryption already available in the project (the `auth.SM4TokenService` uses SM4-GCM). Import the SM4 encryption utility and encrypt the password with `cfg.Auth.SM4Secret` as the key. On load, decrypt it. If SM4 encryption fails (e.g., key not yet available during early startup), fall back to base64 encoding and log a warning.

**3. Register the model in AutoMigrate** in `cmd/server/app.go` - add `&models.SystemSetting{}` to the AutoMigrate list (after existing models, before the closing parenthesis).
