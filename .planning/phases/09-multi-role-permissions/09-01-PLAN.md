   a. Check if users_roles table exists (SELECT FROM sqlite_master)
   b. If exists, return nil (idempotent migration)
   
   c. Create users_roles table:
      ```sql
      CREATE TABLE users_roles (
          user_id INTEGER NOT NULL,
          role_id INTEGER NOT NULL,
          created_at DATETIME,
          updated_at DATETIME,
          PRIMARY KEY (user_id, role_id),
          FOREIGN KEY(user_id) REFERENCES users(id) ON DELETE CASCADE,
          FOREIGN KEY(role_id) REFERENCES roles(id) ON DELETE CASCADE
      )
      ```
   
   d. Migrate existing data (D-08):
      ```sql
      INSERT INTO users_roles (user_id, role_id, created_at, updated_at)
      SELECT id as user_id, role_id, datetime('now'), datetime('now')
      FROM users
      WHERE role_id IS NOT NULL AND role_id > 0
      ```
   
   e. Verify migration (D-18): COUNT users_roles, compare with users COUNT, log warning if mismatch
   
   f. Create indexes: idx_users_roles_user_id, idx_users_roles_role_id

      (SQLite doesn't support DROP COLUMN, leaving deprecated per D-16)

## Threat Model

### Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Database → Migration | SQL execution with DDL privileges |
| Migration → User Data | Bulk data read/write from users table |

### STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-01 | Tampering | users_roles table creation | mitigate | Verify table doesn't exist before creation (pragma_table_info check) |
| T-09-02 | Denial of Service | Data migration INSERT | mitigate | Validate migration preserves all users (COUNT comparison, warning logged) |
| T-09-03 | Information Disclosure | role_id column | accept | Data is NULLed, not deleted; safe to leave deprecated column |
| T-09-04 | Tampering | Migration rollback | mitigate | Down() restores single role (lossy but safe), logs warning about multi-role data loss |
| T-09-05 | Elevation of Privilege | Foreign key CASCADE | accept | CASCADE intended: deleting user/role should remove junction records |
