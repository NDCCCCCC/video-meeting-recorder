## Interaction Patterns

### Multi-Role Selection (D-14)

**Location:** User Management Modal → Role Form.Item (lines 401-412)

**Current:**
```tsx
<Select placeholder="请选择角色">
  <Select.Option value={1}>管理员</Select.Option>
  {/* ... 3 more options */}
</Select>
```

**Target:**
```tsx
<Form.Item
  name="role_ids"
  label="角色"
  rules={[{ required: true, message: '请选择至少一个角色' }]}
>
  <Select
    mode="multiple"
    placeholder="请选择角色（可多选）"
    options={[
      { label: '管理员', value: 1 },
      { label: '操作员', value: 2 },
      { label: '查看者', value: 3 },
      { label: 'API客户端', value: 4 },
      { label: '共享查看者', value: 5 },
    ]}
    tagRender={(props) => {
      const { label, value, ...restProps } = props
      if (value === 5) {
        return <Tag {...restProps} color="purple">{label}</Tag>
      }
      return <Tag {...restProps}>{label}</Tag>
    }}
  />
</Form.Item>
```

**Behavior changes:**
- Single selection → multiple selection (user can have 1-5 roles)
- Dropdown shows checkboxes for multi-select
- Selected roles display as closeable tags
- Shared viewer tag renders in purple

**Validation:** At least 1 role required; shared_viewer requires admin check (D-13)

### Role Badge Display in Table (D-14)

**Location:** User Table → Role Column (lines 221-225)

**Current:**
```tsx
{
  title: '角色',
  dataIndex: 'role',
  width: 120,
  render: (role) => role?.name || '-',
}
```

**Target:**
```tsx
{
  title: '角色',
  dataIndex: 'roles',
  width: 200,
  render: (roles) => (
    <>
      {roles?.map((role) => (
        <Tag
          key={role.id}
          color={role.name === 'shared_viewer' ? 'purple' : 'blue'}
          style={{ marginBottom: 4 }}
        >
          {role.description || role.name}
        </Tag>
      ))}
    </>
  ),
}
```

**Behavior changes:**
- Single role text → array of role badges
- Vertical stacking if user has 3+ roles
- Shared viewer badge in purple (#9254de)
- Other roles in blue (default Ant Design)

### Admin-Only Shared Viewer Assignment (D-13)

**Location:** Submit Handler (lines 114-147)

**Behavior:**
```tsx
const handleSubmit = async () => {
  try {
    const values = await form.validateFields()

    // Admin check for shared_viewer assignment
    if (values.role_ids?.includes(5)) {
      const currentUser = getCurrentUser() // from auth context
      if (!currentUser?.roles?.some(r => r.name === 'admin')) {
        message.error('仅管理员可分配"共享查看者"角色')
        return
      }
    }

    // ... existing API call logic
    // Change role_id to role_ids in request
    const req: UpdateUserRequest = {
      // ... other fields
      role_ids: values.role_ids, // was role_id
    }
  }
}
```

**Error states:**
- Non-admin user attempts to assign shared_viewer: "仅管理员可分配'共享查看者'角色"
- API validation failure: "角色分配失败：{error}"

## Data Mapping

### Frontend Type Changes

**Before:**
```typescript
interface UserInfo {
  id: number
  username: string
  role_id: number  // single role
  role?: { id: number; name: string; description: string }
  // ... other fields
}
```

**After:**
```typescript
interface UserInfo {
  id: number
  username: string
  roles: Array<{ id: number; name: string; description: string }>  // multiple roles
  // ... other fields (role_id removed)
}

interface CreateUserRequest {
  username: string
  password: string
  email?: string
  full_name?: string
  role_ids: number[]  // was role_id
  is_active?: boolean
}

interface UpdateUserRequest {
  email?: string
  full_name?: string
  role_ids: number[]  // was role_id
  is_active?: boolean
}
```

## Accessibility

### Keyboard Navigation
- Multi-select: Arrow keys to navigate options, Space to toggle, Enter to confirm
- Tag removal: Focus tag + Backspace/Delete to remove
- Tab order: Username → Password → Email → Name → Roles → Status → Submit

### Screen Reader Support
- Select multiple: "请选择角色，多选下拉框，已选择 {n} 个角色"
- Shared viewer tag: "共享查看者角色，紫色标签"
- Role array: "用户拥有以下角色：{role1}, {role2}, {role3}"

### Color Contrast
- Purple (#9254de) on white: WCAG AA compliant (4.5:1)
- Blue (#1890ff) on white: WCAG AA compliant (4.5:1)

## State Management

### Form State
```typescript
// Initial state (new user)
form.setFieldsValue({
  username: '',
  password: '',
  email: '',
  full_name: '',
  role_ids: [],  // was role_id: undefined
  is_active: true,
})

// Edit state (existing user with roles)
form.setFieldsValue({
  username: user.username,
  email: user.email,
  full_name: user.full_name,
  role_ids: user.roles.map(r => r.id),  // was role_id: user.role_id
  is_active: user.is_active,
})
```

### Loading States
- Submitting: Disable submit button, show "保存中..." loading state
- Role validation: Debounce admin check for shared_viewer
- API error: Re-enable submit button, show message.error

## Testing Scenarios

### Happy Path
1. Admin creates user with single role (operator) → success
2. Admin creates user with multiple roles (operator + viewer) → success
3. Admin creates user with shared_viewer role → success
4. Non-admin creates user without shared_viewer → success

### Error Path
1. Non-admin attempts to assign shared_viewer → error message "仅管理员可分配..."
2. User submits form without selecting roles → validation error "请选择至少一个角色"
3. API returns 400 for invalid role_ids → display error message
4. API returns 403 for permission denied → display "权限不足"

### Edge Cases
1. User has all 5 roles → badge display wraps to multiple lines
2. User loses all roles (should not happen) → display "-" in role column
3. Role filter dropdown shows shared_viewer option → filter works correctly

## Performance Considerations

### API Optimization
- Batch role assignment: Single API call with `role_ids: []` array
- Cache role list: Load roles once on page mount, reuse in options
- Debounce validation: 300ms delay for admin check

### Rendering
- Role badges: React key on role.id prevents re-renders
- Multi-select tags: Ant Design virtualization for large lists (not needed here, max 5 roles)
