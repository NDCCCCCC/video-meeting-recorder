<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| filesystem → config loader | Operator-controlled CA bundle path and PEM bytes enter the process; malformed/untrusted input must not create a partial trust store. |
| config → Huawei manager | Typed `CABundleFile` and env override cross from deployment configuration into startup security policy. |
| Huawei manager → TLS client | A validated `*x509.CertPool` is shared with clients created after startup; nil intentionally delegates to system roots. |
| application → Huawei terminal | Credentials and session cookies cross an HTTPS boundary whose peer identity must be verified with `InsecureSkipVerify=false`. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-01 | Spoofing / Information Disclosure | `internal/huawei/client.go` TLS handshake | mitigate | Set `tls.Config.RootCAs` to the operator-selected private CA pool while preserving `InsecureSkipVerify=false`, TLS minimum, and cipher policy; prove with real certificate verification tests. |
| T-26-02 | Tampering | `Manager.SetCABundle` PEM ingestion | mitigate | Decode and parse every certificate into a fresh pool, reject bad/trailing/zero-cert input, and publish only after complete success so no partially trusted pool is observable. |
| T-26-03 | Denial of Service | missing or malformed deployment bundle | mitigate | Return path-bearing wrapped errors and invoke startup `logger.Fatal`; fail before Huawei connector construction rather than repeatedly failing during recording. |
| T-26-04 | Information Disclosure | logs around CA loading | mitigate | Log only path/status/error cause; never log PEM bytes, certificates, credentials, session cookies, or private material. |
| T-26-05 | Elevation of Privilege | empty-path compatibility branch | accept | `RootCAs=nil` intentionally uses Go system roots and retains certificate verification; this is the documented compatibility behavior, not a skip-verify bypass. |
| T-26-06 | Repudiation | CA bundle load event | mitigate | INFO-level structured log (`path`, `cert_count`, `pool_kind=system\|custom`) emitted on every successful load at startup; failures funnel through `logger.Fatal` with path + wrapped cause. No CA material is logged. The audit trail for who changed the deployment config is owned by the operator's deployment system (Ansible/manifests), not by this hotfix. |
| T-26-SC | Tampering | npm/pip/cargo installs | accept | No package-manager install or new dependency exists in this plan; implementation and tests use Go stdlib plus already-pinned project dependencies. |
</threat_model>
