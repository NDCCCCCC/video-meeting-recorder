## Background Context

**From Phase 1 (Video Splitting):**
- VideoFile model has `source_type` field (recording/snapshot/split)
- VideoFile model has `parent_id` field (NULL for original recordings)
- Only split/snapshot files should be renameable (D-13: original recordings are immutable)

**From Phase 3 (PPT Management):**
- PPTFile model has `source_type` field (transcription/merge)
- PPT files are generated from transcription or merge operations
- Ownership validation pattern: `middleware.GetUserID(c)` compared with `file.CreatedBy`

**Key Constraints:**
- D-13: Original recordings (source_type='recording', parent_id=NULL) are immutable
- Atomic rename: must update both DB record and physical file system
- Ownership check: only file creator can rename
- File extension must be preserved (.mp4 for videos, .pptx for PPTs)

  <behavior>
    - Test 1: Rename split video successfully updates DB filename and physical file path
    - Test 2: Rename preserves file extension (.mp4)
    - Test 3: Rename fails for original recording (source_type='recording', parent_id=NULL)
    - Test 4: Rename fails when user doesn't own the file
    - Test 5: Physical file rename failure rolls back DB changes
    - Test 6: Duplicate filename in same directory returns error
  </behavior>
  <action>
    Add `RenameVideoFile(id uint, newName string, userID uint) error` method to VideoFileService:
    
    1. **Validation Layer:**
       - Load VideoFile by ID, return error if not found
       - Check ownership: `file.CreatedBy == userID`, return forbidden if mismatch
       - Check immutability: if `file.SourceType == 'recording' && file.ParentID == nil`, return error "Cannot rename original recordings"
       - Validate newName: not empty, max 200 chars, no path separators
       - Preserve extension: extract current ext from file.FilePath, append to newName if missing
       - Check duplicate: query DB for same parent_id + filename combination
    
    2. **Atomic Rename Operation:**
       - Start database transaction
       - Construct new file path: `dir(newPath) + newName + ext`
       - Rename physical file: `os.Rename(oldPath, newPath)`
       - If os.Rename fails: rollback transaction, return error
       - Update DB record: `file.FileName = newName + ext`, `file.FilePath = newPath`
       - Commit transaction
    
    3. **Error Handling:**
       - Return descriptive errors for each validation failure
       - On filesystem failure, log warning and rollback DB
       - Use gorm.ErrRecordNotFound for missing files
  </action>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client → API | Untrusted rename requests cross here |
| API → Service | Authenticated requests with userID |
| Service → Filesystem | Atomic rename operations |
| Service → Database | Transactional updates |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Spoofing | Rename handlers | mitigate | Require SM4Auth middleware, validate userID matches file.CreatedBy |
| T-05-02 | Tampering | Filesystem rename | mitigate | Atomic transaction (DB + filesystem), rollback on failure |
| T-05-03 | Repudiation | Rename operations | mitigate | Log all rename operations with userID, timestamp, old name, new name |
| T-05-04 | Information Disclosure | Error messages | mitigate | Return generic errors to client, log details server-side |
| T-05-05 | Denial of Service | Duplicate filenames | mitigate | Check for duplicates before rename, return descriptive error |
| T-05-06 | Elevation | Ownership check | mitigate | Validate file.CreatedBy == userID for both VideoFile and PPTFile (via SourceVideoFile) |
| T-05-07 | Tampering | Path traversal | mitigate | Reject path separators (/ \) in new_name, construct paths with filepath.Join() |
| T-05-08 | Tampering | Extension swap | mitigate | Preserve original extension, ignore user-provided extension |
</threat_model>
