## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Icon gaps, inline padding |
| sm | 8px | Compact element spacing, button internal padding |
| md | 16px | Default element spacing, page container padding |
| lg | 24px | Section padding, card margins, modal content padding |
| xl | 32px | Layout gaps between major sections |
| 2xl | 48px | Major section breaks |
| 3xl | 64px | Page-level spacing (rarely used) |

**Exceptions (Semantic Breakpoints - justified):**
- Sidebar thumbnail width: 200px (fixed, per CONTEXT.md D-02 - optimal for 16:9 thumbnails with padding)
- Thumbnail size: 160x88px (16:9 aspect ratio for preview consistency, 88px = multiple of 4)
- Merge selection bar height: 128px (from 120px - using standard 2xl+xl spacing to accommodate drag-to-reorder thumbnails with proper touch targets)
- Main view minimum height: 400px (for slide preview clarity)

**Source:** Phase 1-2 UI-SPEC spacing scale (inherited), CONTEXT.md decisions D-02, D-14

## Color

**Color Distribution:**
- **Dominant surfaces: 60%** - #f0f2f5 (page background, major surfaces, preview area background)
- **Secondary surfaces: 30%** - #ffffff (cards, modals, content areas, thumbnail sidebar)
- **Accent elements: 10%** - #1890ff (reserved for specific interactive elements only)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | #f0f2f5 | Page background, major surfaces, preview area background |
| Secondary (30%) | #ffffff | Cards, modals, content areas, thumbnail sidebar |
| Accent (10%) | #1890ff | Primary actions, selected states, active slide borders, merge mode activation |
| Destructive | #ff4d4f | Delete actions, error states, slide removal in merge mode |
| Warning | #faad14 | Processing states, slide extraction in progress |
| Success | #52c41a | Transcription completion, successful merge |

**Accent color reserved for these 6 specific elements ONLY:**
1. "预览PPT" button in file list action column
2. Selected slide thumbnail border (2px solid #1890ff)
3. "合并幻灯片" button in result page action panel
4. "确认合并" button in merge mode
5. Merge selection bar border (top 2px solid #1890ff)
6. Gallery switcher selected result highlight (border + background)

**Never use accent color (#1890ff) for:**
- Secondary or tertiary buttons (use default button styles)
- Disabled states (use Ant Design disabled colors)
- Text body or labels (use #262626 for primary text, #8c8c8c for secondary)
- Border lines or dividers (except merge mode active state)
- Failed transcription states (use destructive color #ff4d4f)
- Loading spinners (use Ant Design Spin default)
- Background fills (use dominant or secondary colors)
- Hover states for non-interactive elements

**Warning color usage:**
- "正在生成预览..." loading state during first slide extraction
- Slide extraction progress indicator
- PPT regeneration status

**Source:** Phase 1-2 UI-SPEC color system (inherited), CONTEXT.md decisions D-02, D-13, D-14

## Interaction Patterns

### PPT Preview Navigation Flow

```
User clicks "预览PPT" button in file list
  ↓
Navigate to /results/:videoFileId
  ↓
Fetch all PPT results for this video: GET /api/v1/videos/:id/ppts
  ↓
Select newest result (default per CONTEXT.md D-12)
  ↓
Fetch slide images: GET /api/v1/ppts/:id/slides
  ↓ [First preview, cache miss]
Show "正在生成预览..." loading indicator
  ↓
Backend extracts slides (thumbnails + full-size)
  ↓
Update preview with slide images
  ↓ [Subsequent previews, cache hit]
Display cached images immediately (no loading)
  ↓
User navigates slides:
  - Click thumbnail in sidebar: Jump to slide
  - Click page input: Direct jump to page number
  - Keyboard arrows: Previous/next slide
  - Click "全屏演示": Enter full-screen mode
  ↓
User interacts with per-slide actions:
  - "下载此页": Download single slide image
  - "复制图片": Copy slide to clipboard
  - "退出全屏": Return to normal preview mode
```

**Validation:**
- PPT file must exist and be accessible
- Slide cache directory must be readable
- Page number must be within valid range (1 to total)

**Error states:**
- Slide extraction failed: "PPT预览加载失败：无法提取幻灯片。请重新转录或联系管理员。"
- Slide image missing: Show placeholder with slide number
- Invalid page number: Clamp to valid range, show toast: "页码超出范围，已跳转到第{validPage}页"

**Source:** CONTEXT.md decisions D-01, D-03, D-06, D-09

### Slide Merge Flow

```
User views result page
  ↓
Click "合并幻灯片" button in action panel
  ↓
Enter merge mode:
  - Sidebar thumbnails become selectable
  - Bottom bar appears: "已选择 0/200 页"
  - "合并幻灯片" button changes to "取消合并"
  ↓
User clicks thumbnails to select/deselect slides
  ↓
Selected slides appear in bottom bar with drag handles
  ↓
User drags slides in bottom bar to reorder (dnd-kit)
  ↓
User clicks "确认合并" button
  ↓
Validate selection (max 200 slides)
  ↓ [Validation passes]
API call: POST /api/v1/ppts/merge
  ↓
Show loading spinner during merge
  ↓
Merge completes, show toast: "合并完成！已生成 {pageCount} 页PPT。"
  ↓
Exit merge mode
  ↓
Refresh result gallery to show merged PPT (newest result)
  ↓ [Validation fails]
Show error toast: "最多只能选择200页幻灯片进行合并。"
  ↓
Disable "确认合并" button until selection within limit
```

**Merge mode states:**

| Element | Normal Mode | Merge Mode |
|---------|-------------|------------|
| Sidebar thumbnails | Click to navigate | Click to select/deselect |
| Thumbnail overlay | None | Checkmark (bottom-right) on select |
| Page indicator | Visible | Hidden |
| Per-slide actions | Visible | Hidden |
| Gallery strip | Clickable | Disabled (greyed out) |
| Bottom bar | Hidden | Visible with selected slides |
| Action buttons | All enabled | Only "取消合并" and "确认合并" enabled |

**Keyboard shortcuts in merge mode:**
- ESC: Exit merge mode (with confirmation if slides selected)
- Ctrl+A: Select all slides in current PPT
- Ctrl+D: Deselect all slides

**Source:** CONTEXT.md decisions D-13, D-14, D-15, D-16, D-17, D-18

## Performance Considerations

### Slide Image Caching

| Strategy | Implementation |
|----------|----------------|
| On-demand extraction | Extract slides only on first preview (CONTEXT.md D-03) |
| File system cache | Store in `recordings/ppts/{pptFileID}/slides/` |
| Dual resolution | Thumbnails 200x112px (fast loading), full-size 1920x1080px |
| Cache invalidation | Check cache directory creation time vs PPTFile.UpdatedAt |
| Lazy loading | Load thumbnails first, full-size images on scroll |

**Cache miss handling:**
- Show "正在生成预览..." loading indicator
- Trigger async slide extraction (Python script)
- Poll for cache completion every 2 seconds
- Update preview when extraction completes

**Source:** CONTEXT.md decisions D-03, D-04; RESEARCH.md §Pitfalls 2 (Cache Miss Storm)

### Preview Rendering Performance

| Optimization | Implementation |
|-------------|----------------|
| Thumbnail virtualization | React-window or react-virtualized for long PPTs (>100 slides) |
| Image lazy loading | Intersection Observer API for full-size images |
| Memoization | useMemo for slide list, useCallback for navigation handlers |
| Debounced page input | 300ms debounce before jumping to page |
| Preload adjacent slides | Preload ±2 slides from current slide |

**Merge mode performance:**
- Limit drag-and-drop re-renders with dnd-kit's optimized sensors
- Debounce selection state updates (100ms)
- Virtualize merge selection bar if >50 slides selected

### Memory Management

| Concern | Mitigation |
|---------|-----------|
| Large slide images in memory | Unload off-screen slides from DOM, keep only current ±5 slides |
| Merge mode state bloat | Limit to 200 slides max (CONTEXT.md D-17), cleanup on unmount |
| Slide extraction memory | Limit concurrent extractions (max 3 at a time), process in queue |
| Image cache size | Implement LRU cache for slide images (max 100MB) |

**Source:** RESEARCH.md §Pitfalls 2 (Cache Miss Storm), §Performance Considerations
