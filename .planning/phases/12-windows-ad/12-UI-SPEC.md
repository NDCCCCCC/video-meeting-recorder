## Interaction Patterns

### Configuration Page Flow

1. **Initial Load** → Show current authentication mode (local/ad) with Tag indicator
2. **View Configuration** → Display AD config form (disabled if in local mode)
3. **Edit Configuration** → Enable form inputs, show "Test Connection" button
4. **Test Connection** → Call validation API, show 4-layer progress, display result
5. **Save Configuration** → Validate automatically, block save on failure, show success message
6. **Switch to AD Mode** → Require successful config validation, show confirmation modal, apply change

### Security Warning Display

- **Passive logging** (D-13): Warning shown but no explicit confirmation required
- **Inline display** (D-12): Warning icon (⚠️) next to port field
- **Audit trail**: Log warning display in audit logs for compliance

### Error Handling States

| State | Display | Action |
|-------|---------|--------|
| Connection timeout | "连接超时，请检查网络和防火墙设置" | Retry button |
| Invalid credentials | "管理员账号或密码错误" | Re-enter BindDN/password |
- TLS certificate error | "TLS证书验证失败，请检查证书配置" | Show certificate help |
| User search failed | "无法搜索用户，请检查BaseDN配置" | Verify BaseDN format |

**Source:** CONTEXT.md D-15 to D-17 validation flow, Spike 005 validation layers.

## API Integration Points

| Endpoint | Method | Purpose | UI Trigger |
|----------|--------|---------|------------|
| /api/admin/auth/config | GET | Fetch current AD config and auth mode | Page load |
| /api/admin/auth/ad/test-connection | POST | Validate AD configuration (4-layer) | Test connection button |
| /api/admin/auth/config | PUT | Save AD configuration | Save config button |
| /api/admin/auth/mode | PUT | Switch authentication mode | Mode switch toggle |

**Request/Response formats:**

```typescript
// Test connection request
interface TestConnectionRequest {
  server: string        // ad.example.com:636
  port: number          // 636 or 389
  bind_dn: string       // cn=admin,cn=users,dc=example,dc=com
  password: string      // Admin password
  base_dn: string       // dc=example,dc=com
  use_tls: boolean      // true for LDAPS
}

// Test connection response
interface TestConnectionResponse {
  valid: boolean
  level: number         // 1-4 validation layers
  message: string       // User-friendly message
  errors?: string[]     // Validation errors if failed
  warnings?: string[]   // Warnings (e.g., port 389)
  response_time: number // Connection time in ms
}
```

**Source:** CONTEXT.md specific ideas section, Spike 005 validation API design.
