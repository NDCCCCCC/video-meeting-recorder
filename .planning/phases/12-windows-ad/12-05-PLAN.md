    # Windows AD域控认证 - 管理员指南

    ## 概述

    Record V2系统支持Windows Active Directory域控认证，允许用户使用AD账号登录系统。系统支持两种认证模式：
    - **本地认证 (local)**: 使用系统内创建的本地账号密码登录
    - **AD域控认证 (ad)**: 使用Windows Active Directory域控账号登录

    ## 配置步骤

    ### 1. 准备工作

    在启用AD认证前，请确保：
    - 有可访问的AD域控服务器
    - 拥有AD域控管理员账号（用于系统连接AD）
    - 知道AD服务器的以下信息：
      - 服务器地址和端口（推荐636端口LDAPS）
      - BindDN（管理员DN）
      - BaseDN（域的DN）
    - 前端SM4加密密钥已配置（与本地认证相同）

    ### 2. 配置AD认证

    1. 使用管理员账号登录系统
    2. 导航到：系统设置 > 域控认证
    3. 在"认证模式"下拉框中选择"AD域控认证"
    4. 填写AD服务器配置：
       - **AD服务器地址**: 例如 `ad.example.com:636`
         - 生产环境推荐使用636端口（LDAPS加密）
         - 内部测试环境可使用389端口（LDAP明文，会有安全警告）
       - **BindDN**: 管理员DN，例如 `cn=admin,cn=users,dc=example,dc=com`
       - **管理员密码**: AD管理员密码（输入后加密存储）
       - **BaseDN**: 域的DN，例如 `dc=example,dc=com`
       - **启用LDAPS**: 推荐勾选（使用636端口加密传输）
    5. 点击"测试连接"按钮
       - 系统会进行4层验证：
         - 第1层：配置格式验证
         - 第2层：网络连接测试
         - 第3层：管理员认证测试
         - 第4层：用户搜索功能测试
    6. 确认测试结果显示"连接测试成功"
    7. 点击"保存配置"

    ### 3. 端口选择说明

    **LDAPS端口636（推荐）**
    - ✅ 加密传输，安全性高
    - ✅ 适合生产环境
    - ✅ 推荐用于公网环境

    **LDAP端口389（仅内网测试）**
    - ⚠️ 明文传输，存在安全风险
    - ⚠️ 系统会显示安全警告
    - ⚠️ 警告会记录到审计日志
    - ⚠️ 仅建议在隔离的内网测试环境使用

    ### 4. AD用户登录流程

    首次使用AD账号登录时：
    1. 用户在登录页面输入AD账号和密码
    2. 系统连接到AD服务器验证账号密码
    3. 验证成功后，系统自动创建本地用户记录：
       - 用户名 = AD账号名
       - 邮箱 = AD邮箱
       - 姓名 = AD显示名称
       - 部门 = AD部门信息
       - 自动分配默认角色（查看者）
       - 生成本地随机密码（AD用户不会使用）
    4. 返回JWT令牌，用户可以正常使用系统

    **注意**: AD用户的权限通过本地角色管理，可以由管理员在"用户管理"页面调整角色和权限。

    ## 故障排查

    ### 问题1: 连接测试失败 - "无法解析服务器地址"
    **原因**: DNS无法解析AD服务器地址
    **解决**:
    - 检查服务器地址拼写是否正确
    - 尝试使用IP地址代替域名
    - 检查网络连接是否正常

    ### 问题2: 连接测试失败 - "连接被拒绝"
    **原因**: 防火墙阻止或LDAP服务未启动
    **解决**:
    - 检查AD服务器防火墙是否开放636或389端口
    - 确认AD服务器的LDAP服务正在运行
    - 使用telnet测试端口连通性：`telnet ad.example.com 636`

    ### 问题3: 连接测试失败 - "管理员用户名或密码错误"
    **原因**: BindDN或密码不正确
    **解决**:
    - 检查BindDN格式是否正确
    - 确认管理员密码是否正确
    - 确认管理员账号有权限访问AD

    ### 问题4: 连接测试失败 - "TLS证书错误"
    **原因**: LDAPS证书验证失败
    **解决**:
    - 生产环境：配置正确的CA证书
    - 测试环境：可临时使用"跳过证书验证"选项（不推荐生产使用）

    ### 问题5: AD用户登录失败 - "域控账号不存在"
    **原因**: AD中不存在该账号
    **解决**:
    - 确认账号在AD中存在
    - 检查BaseDN配置是否正确
    - 确认账号没有被删除或禁用

    ### 问题6: AD用户登录失败 - "域控账号已禁用"
    **原因**: AD账号已被禁用
    **解决**:
    - 联系AD管理员检查账号状态
    - 在AD中启用该账号

    ## 安全建议

    1. **生产环境必须使用LDAPS (636端口)**
       - LDAP 389端口明文传输密码，存在严重安全风险
       - 系统会显示警告并记录到审计日志

    2. **保护AD管理员密码**
       - 密码加密存储在配置文件中
       - 建议使用环境变量存储密码
       - 定期更换管理员密码

    3. **最小权限原则**
       - AD管理员账号只需有读取用户信息的权限
       - 不需要域管理员权限

    4. **审计日志**
       - 所有认证模式切换都会记录到审计日志
       - 包括操作人、操作时间、配置内容
       - 定期检查审计日志

    ## 技术细节

    ### 支持的LDAP协议版本
    - LDAP v3 (通过go-ldap/v3库)
    - TLS 1.2或更高版本

    ### AD用户属性映射
    | AD属性 | 本地字段 | 说明 |
    |--------|---------|------|
    | sAMAccountName | username | 登录账号名 |
    | mail | email | 邮箱地址 |
    | displayName | full_name | 显示名称 |
    | department | ad_department | 部门 |
    | userPrincipalName | ad_upn | 用户主体名称 |
    | objectGUID | ad_guid | 全局唯一标识符 |
    | distinguishedName | ad_dn | 可分辨名称 |

    ### 用户账号控制检查
    系统会检查AD账号的userAccountControl属性：
    - ACCOUNTDISABLE (0x0002): 账号已禁用，拒绝登录
    - 其他标志也会检查并记录到日志

    ## 配置示例

    ### config.yaml 配置文件
    ```yaml
    auth:
      mode: ad  # 认证模式: local 或 ad
      sm4_secret: "${SM4_SECRET:your-sm4-secret-key}"
      access_token_duration: 24h
      ad:
        server: "ad.example.com:636"
        bind_dn: "cn=admin,cn=users,dc=example,dc=com"
        password: "${AD_PASSWORD}"  # 从环境变量读取
        base_dn: "dc=example,dc=com"
        use_tls: true  # 推荐true（LDAPS），false为LDAP
        pool_size: 10
        dial_timeout: 10  # 秒
        request_timeout: 30  # 秒
        insecure_skip_verify: false  # 生产环境必须false
    ```

    ### 环境变量
    ```bash
    export AD_PASSWORD="your-ad-admin-password"
    export SM4_SECRET="your-sm4-encryption-key"
    ```

    ## 常见问题

    **Q: 切换到AD模式后，本地用户还能登录吗？**
    A: 不能。切换到AD模式后，所有用户必须使用AD账号登录。如需本地认证，请切换回local模式。

    **Q: AD用户可以在系统中修改密码吗？**
    A: 不能。AD用户的密码由AD域控制器管理，如需修改密码请联系域管理员。

    **Q: 如何为AD用户分配权限？**
    A: AD用户首次登录时自动创建本地记录并分配默认角色（查看者）。管理员可以在"用户管理"页面为AD用户分配其他角色和权限。

    **Q: 系统支持多个AD服务器吗？**
    A: 当前版本仅支持单个AD服务器配置。

    **Q: AD用户删除后，本地记录会自动删除吗？**
    A: 不会。AD用户删除后，本地记录仍然保留，但无法再使用AD账号登录。管理员需要手动删除本地用户记录。
