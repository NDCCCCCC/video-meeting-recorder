## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-20-01-log-leak | Information Disclosure | Service-layer zap.Error still logs full err | accept | zap.Error(err) ALREADY logs the full err.Error() — this plan does NOT change that. SentinelField ADDS a structured tag (sentinel_type=ErrXxx) without removing or altering zap.Error's content. No new leak surface; pre-existing log content unchanged. If err.Error() contains PII, that's a pre-existing concern out of phase scope. |
| T-20-03-adhoc-visibility | Repudiation (monitoring blind spot) | Unknown errors emit sentinel_type="ad-hoc" | mitigate | This is the PRIMARY security uplift of the plan: ad-hoc errors now have a searchable tag in logs, enabling ops to query `sentinel_type=ad-hoc` and identify unhandled error paths. Turns a blind spot into a monitored signal. |
| T-20-middleware-boundary | Tampering | error_mapper.go D-03.7 boundary | mitigate | D-03.7 locks "no behavior extension" — this plan adds ONLY a log field, with explicit code comment + commit message documenting the boundary. The middleware still calls HandleError exactly once per error; c.Writer.Written() guard unchanged. TestErrorMapper (if exists) still passes. |
| T-20-SC-supply-chain | Tampering | No new packages | accept | pkg/response already exists; no new external deps. |
