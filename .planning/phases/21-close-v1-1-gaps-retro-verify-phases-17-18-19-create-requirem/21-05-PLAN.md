- `func HandleError(c *gin.Context, err error) bool`
- `if err == nil || c.Writer.Written() { return false }` — 不写响应, 返回 false
- 否则: 调用 `errors.MapToHTTPStatus(err)` 得 (httpStatus, respCode, message), 调 `GinErrorWithStatus(c, ...)`, 返回 `errors.IsKnownError(err)`
- 已知 sentinel / BusinessError → 写对应状态码 + 返回 true
- unknown error → 写 500 + 返回 **false** (不是 true — CONTEXT D-04.2 此处理由有误, 已被 21-RESEARCH §6 推翻)

- 当前 `if response.HandleError(c, err) { return }; // 兜底; return` 两条分支:
  - 分支 A (known 错误): HandleError 返回 true → 进 if 内 return (已写响应)
  - 分支 B (unknown 错误): HandleError 返回 false → 落到裸 return (HandleError 已写 500)
- 两条分支都是「先写响应再 return」, 与 `response.HandleError(c, err); return` 观察等价
- HandleError 实际返回 `IsKnownError(err)` (known→true, unknown→false), 但因两条分支都 return, 返回值无关紧要
