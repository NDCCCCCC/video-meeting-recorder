<objective>
Integrate video playback with PPT viewer, enabling users to click slides to jump to corresponding video timestamps.

This plan adds a synchronized video preview panel alongside the PPT viewer. When users click on a slide, the video automatically seeks to the timestamp where that slide was captured. This provides context for slide content and allows users to verify slide accuracy against the original video.

**Purpose:** Enable slide-to-video navigation for content verification and context understanding.

**Output:**
- VideoPreviewPanel component with embedded video player
- TimestampMapper service for slide-to-time mapping
- API endpoint for timestamp data
- Bidirectional sync between PPT and video playback
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted videoFileId in URL params |
| API→database | Trusted timestamp queries with user-scoped data |
| client→video stream | Video file access (must validate ownership) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-09 | Spoofing | Timestamp map access | mitigate | Validate user ownership of VideoFile via middleware.GetUserID before returning timestamps |
| T-06-10 | Information Disclosure | Video file path | mitigate | Use authenticated streaming endpoint, validate ownership before serving video bytes |
| T-06-11 | Denial of Service | Large timestamp maps | mitigate | Limit timestamp map size to 1000 slides, return 413 if larger, cache results with TTL |
| T-06-12 | Tampering | Client-side timestamp manipulation | mitigate | Timestamps are server-generated from TranscriptionTask, client cannot modify mapping |
| T-06-13 | Escalation of Privilege | Cross-user video access | mitigate | Video streaming endpoint must validate user owns VideoFile, check VideoFile.UserID or SourceVideoFileID ownership chain |
</threat_model>
