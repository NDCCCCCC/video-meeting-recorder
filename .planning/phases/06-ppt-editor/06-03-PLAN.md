<objective>
Implement slide capture from video and insertion into PPT, enabling users to add missing slides or capture specific moments.

This plan adds the ability to capture a video frame at the current playback timestamp and insert it as a new slide into the PPT. Users can preview the captured frame, choose the insertion position, and regenerate the PPT with the new slide included. This completes the PPT editing workflow by allowing users to fix missing slides or capture important moments that were skipped during automatic extraction.

**Purpose:** Enable users to manually capture and insert slides to fix gaps or add important content from the video.

**Output:**
- FrameCaptureService for extracting frames at specific timestamps
- Slide insertion API endpoints
- SlideCapturePanel UI component with preview and insertion controls
- Integration with video preview for timestamp-based capture
- Backup and rollback support for insertion operations
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted timestamp, untrusted frame data, untrusted insert_position |
| API→filesystem | Video file paths, slide cache paths, PPTX file paths |
| API→FFmpeg | FFmpeg command execution (must validate inputs) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-14 | Spoofing | Frame capture API | mitigate | Validate user owns both PPTFile and source VideoFile via ownership check |
| T-06-15 | Tampering | timestamp parameter | mitigate | Validate timestamp is within video duration (ffprobe check), clamp to valid range |
| T-06-16 | Tampering | insert_position parameter | mitigate | Validate position is within [1, page_count+1], reject invalid positions with 400 error |
| T-06-17 | Tampering | frame_data (base64) | mitigate | Decode and validate JPEG header, reject invalid/malicious images, limit size to 10MB |
| T-06-18 | Denial of Service | Large frame captures | mitigate | Limit frame size to 10MB, limit capture rate (max 10/min per user), return 429 if exceeded |
| T-06-19 | Denial of Service | Frequent insertions | mitigate | Limit insertions to 10 per PPT per hour, enforce via EditHistory check |
| T-06-20 | Escalation of Privilege | Cross-user PPT modification | mitigate | Validate ownership on both capture and insert endpoints, check SourceVideoFileID ownership chain |
| T-06-21 | Information Disclosure | Video file exposure | mitigate | Ensure video path is not returned in API responses, validate video file ownership before serving |
</threat_model>
