<objective>
Create frontend video preview component with slide-to-video synchronization, enabling users to view video playback alongside PPT slides and navigate by clicking slides.

This plan implements the video preview panel that integrates with the PPT viewer. When users click on a slide, the video automatically seeks to the timestamp where that slide was captured. This provides context for slide content and allows users to verify slide accuracy against the original video.

**Purpose:** Enable synchronized video playback with slide navigation for content verification.

**Output:**
- VideoPreviewPanel component with HTML5 video player
- Timestamp loading and caching
- Bidirectional slide-to-video sync
- Integration into results page with toggle control
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-14 | Spoofing | Video stream access | mitigate | Use authenticated streaming endpoint /api/v1/videos/:id/stream with ownership validation |
| T-06-15 | Information Disclosure | Timestamp exposure | mitigate | Timestamps only returned for user-owned videos via API authentication |
| T-06-16 | Denial of Service | Large video files | mitigate | Use streaming endpoint (not full download), browser handles buffering |
| T-06-17 | Tampering | Client-side slide manipulation | mitigate | Current slide is UI state only, server validates all operations |
| T-06-18 | Escalation of Privilege | Cross-user video access | mitigate | Video streaming endpoint validates VideoFile ownership before serving bytes |

**Note:** Video streaming endpoint should already exist from earlier phases. If not, this plan assumes it will be created or already exists with proper ownership validation.
