### WR-01: Missing accessibility attributes on Skeleton placeholder

**File:** `frontend/src/components/SlideThumbnail.tsx:117-121`

**Issue:** The Skeleton.Image component lacks accessibility attributes (aria-label, role) when thumbnail_url is not available. Screen readers won't be able to communicate the loading state to users.

**Current code:**
```tsx
) : (
  <Skeleton.Image
    active
    style={{ width: 160, height: 90 }}
  />
)}
```

**Fix:**
```tsx
) : (
  <Skeleton.Image
    active
    style={{ width: 160, height: 90 }}

    role="img"
  />
)}
```

### WR-02: Potential performance issue with inline style mutations

**File:** `frontend/src/components/SlideThumbnail.tsx:79-90`

**Issue:** The onMouseEnter and onMouseLeave handlers directly mutate DOM styles via inline style properties. While this works, it's less performant than using CSS classes and can cause issues if the component unmounts during a transition.

**Current code:**
```tsx
onMouseEnter={(e) => {
  if (!isCurrent && !isDragging) {
    e.currentTarget.style.opacity = '0.8'
    e.currentTarget.style.transform = 'scale(1.02)'
  }
}}
onMouseLeave={(e) => {
  if (!isCurrent && !isDragging) {
    e.currentTarget.style.opacity = '0.6'
    e.currentTarget.style.transform = 'scale(1)'
  }
}}
```

**Fix:** Use CSS classes instead:
```tsx
// Add CSS class definition
const thumbnailClass = isDragging ? 'dragging' : isCurrent ? 'current' : 'inactive'

// In component className:
className={`thumbnail ${thumbnailClass}`}

// In CSS file:
.thumbnail.inactive:hover {
  opacity: 0.8;
  transform: scale(1.02);
}
```

```tsx
  height={THUMBNAIL_HEIGHT}

```

### WR-04: Complex and brittle viewport height calculation

**File:** `frontend/src/pages/results/index.tsx:580`

**Issue:** The maxHeight calculation `calc((100vw - 32px - 160px - 32px) / 2 * 9 / 16)` is complex, hard to maintain, and assumes specific padding values that may not match actual layout. The calculation also uses viewport width (vw) to calculate height, which is unusual.

**Current code:**
```tsx
style={{
  ...
  maxHeight: 'calc((100vw - 32px - 160px - 32px) / 2 * 9 / 16)',
  ...
}}
```

**Fix:** Use a more robust calculation or CSS custom properties:
```tsx
// Option 1: Use viewport height directly with proper offsets
maxHeight: 'calc(100vh - 200px)'  // Account for header + info bar

// Option 2: Use CSS custom properties
maxHeight: 'var(--thumbnail-max-height, calc(100vh - 200px))'

// Option 3: Match the 16:9 preview area height
maxHeight: 'calc((100vh - 250px) * 9 / 16)'  // Assuming preview area uses remaining height
```

### WR-05: Missing visual feedback during lazy image loading

**File:** `frontend/src/components/SlideThumbnail.tsx:99-115`

**Issue:** When `loading="lazy"` triggers and the image starts loading, there's no visual indication to the user that the image is actively loading. The user sees a blank space until the image loads.

**Current code:**
```tsx
<Image
  src={slide.thumbnail_url}
  loading="lazy"
  // No loading state indication
/>
```

**Fix:** Add a loading placeholder or spinner:
```tsx
const [imageLoaded, setImageLoaded] = useState(false)

<Image
  src={slide.thumbnail_url}
  loading="lazy"
  onLoad={() => setImageLoaded(true)}
  style={{ display: imageLoaded ? 'block' : 'none' }}
/>
{!imageLoaded && <Skeleton.Image active style={{ width: 160, height: 90 }} />}
```

### WR-06: Unnecessary re-renders from inline object creation

**File:** `frontend/src/pages/results/index.tsx:585`

**Issue:** The style object for the thumbnail container is recreated on every render, causing unnecessary re-renders of child components even though the style never changes.

**Current code:**
```tsx
<div style={{ display: 'flex', flexDirection: 'column', gap: 8 }}>
  {slides.map((slide, idx) => (...))}
</div>
```

**Fix:** Extract style object to a constant or use useMemo:
```tsx
// Option 1: Extract to constant (outside component)
const THUMBNAIL_LIST_STYLE: React.CSSProperties = {
  display: 'flex',
  flexDirection: 'column',
  gap: 8,
}

// In render:
<div style={THUMBNAIL_LIST_STYLE}>

// Option 2: Use useMemo
const thumbnailListStyle = useMemo(() => ({
  display: 'flex',
  flexDirection: 'column',
  gap: 8,
}), [])
```

### WR-08: Missing secondary fallback for image loading failures

**File:** `frontend/src/components/SlideThumbnail.tsx:106-110`

**Issue:** If the fallback SVG also fails to load (e.g., due to base64 decoding issues or browser limitations), there's no secondary fallback. This could result in a broken image icon.

**Current code:**
```tsx
onError={(e) => {
  const img = e.currentTarget as HTMLImageElement
  img.src = 'data:image/svg+xml;base64,...'  // Only one fallback
}}
```

**Fix:** Add a secondary fallback using a simple colored div:
```tsx
const [imageError, setImageError] = useState(false)

{!imageError && slide.thumbnail_url ? (
  <Image
    src={slide.thumbnail_url}
    onError={(e) => {
      const img = e.currentTarget as HTMLImageElement
      img.src = FALLBACK_THUMBNAIL_SVG
      img.onerror = () => setImageError(true)
    }}
  />
) : (
  <div style={{
    width: 160,
    height: 90,
    background: '#f0f0f0',
    display: 'flex',
    alignItems: 'center',
    justifyContent: 'center',
    color: '#999',
    fontSize: 12,
  }}>
    No Preview
  </div>
)}
```

### IN-02: Inconsistent hover behavior with dragging state

**File:** `frontend/src/components/SlideThumbnail.tsx:79-90`

**Issue:** The hover handlers check `!isDragging` but don't check `!isDraggable`. This means hover effects are disabled during dragging but not when drag mode is simply enabled, which might be inconsistent with user expectations.

**Current code:**
```tsx
onMouseEnter={(e) => {
  if (!isCurrent && !isDragging) {  // Only checks isDragging
    e.currentTarget.style.opacity = '0.8'
    e.currentTarget.style.transform = 'scale(1.02)'
  }
}}
```

**Fix:** Consider also checking drag mode for consistency:
```tsx
onMouseEnter={(e) => {
  if (!isCurrent && !isDragging && !isDraggable) {  // Also check isDraggable
    e.currentTarget.style.opacity = '0.8'
    e.currentTarget.style.transform = 'scale(1.02)'
  }
}}
```
