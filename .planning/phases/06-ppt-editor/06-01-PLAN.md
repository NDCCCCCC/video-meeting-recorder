<objective>
Implement duplicate slide detection and deletion functionality for PPT editing.

This plan enables users to identify and remove duplicate slides from generated PPTs using visual similarity algorithms. The system will detect visually similar slides, present them in a comparison UI, allow selective deletion, regenerate the PPT file, and maintain backups for rollback.

**Purpose:** Reduce PPT file size and improve quality by removing duplicate content that commonly occurs during video frame extraction.

**Output:**
- DuplicateDetectionPanel component for comparing and selecting duplicates
- PPTEditorService with delete and detect operations
- API endpoints for slide management
- Backup and rollback mechanism
</objective>

  <action>
  1. Create PPTEditorService struct:
     ```go
     type PPTEditorService struct {
         db                 *gorm.DB
         logger             *zap.Logger
         config             *config.Config
         slideCache         *SlideCacheService
         similarityDetector *SimilarityDetector
         pptxGenerator      *PPTXGenerator
     }
     ```

  2. Implement `DetectDuplicateSlides(pptFileID uint, threshold float64)`:
     - Get all slides via SlideCacheService.GetOrExtractSlides
     - Load full-size images for each slide
     - Compare each pair using SimilarityDetector.IsFrameChanged
     - Group slides with similarity > threshold (e.g., SSIM > 0.95 or pHash < 3)
     - Return DuplicateGroup struct with slide numbers and similarity scores
     - Cache results to avoid re-scanning (use in-memory map with TTL)

  3. Implement `CreateBackup(pptFileID uint) error`:
     - Load PPTFile from DB
     - Copy FilePath to backup path: `FilePath.bak.{timestamp}`
     - Update PPTFile.BackupPath
     - Return error if backup already exists (prevent overwrite)

  4. Implement `DeleteSlides(pptFileID uint, slideNumbers []int) error`:
     - Validate ownership (user must own this PPT)
     - Call CreateBackup if no backup exists
     - Get all slides via SlideCacheService
     - Filter out deleted slides from slide list
     - Build array of full-size image paths for remaining slides
     - Generate new PPTX via PPTXGenerator.GeneratePPTX
     - Update PPTFile.FilePath to new PPTX
     - Invalidate slide cache via SlideCacheService.InvalidateCache
     - Record deletion in PPTFile.DeletedSlides and EditHistory
     - Update page_count in database

  5. Add DuplicateGroup and DuplicatePair types:
     ```go
     type DuplicateGroup struct {

         Similarity  float64 `json:"similarity"`
         SSIMScore   float64 `json:"ssim_score"`
         PHashDist   int     `json:"phash_distance"`
     }
     ```

  6. Error handling:
     - Return error if trying to delete all slides
     - Return error if PPTFile has no backup and backup creation fails
     - Rollback PPTFile record on failure

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client→API | Untrusted slide numbers, untrusted duplicate detection requests |
| API→database | Trusted SQL queries with user-scoped data |
| API→filesystem | Slide image paths, PPTX file paths (must validate) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-06-01 | Spoofing | DeleteSlides API | mitigate | Validate user ownership via middleware.GetUserID before any operation |
| T-06-02 | Tampering | slide_numbers request body | mitigate | Validate array contains integers within valid range (1 to page_count), reject malformed arrays |
| T-06-03 | Repudiation | Edit history logging | mitigate | Record all edit operations in PPTFile.EditHistory with timestamp and user ID |
| T-06-04 | Information Disclosure | Backup file path | mitigate | Return backup_path only to owner, validate path is within recordings directory before serving |
| T-06-05 | Denial of Service | Duplicate detection | mitigate | Cache detection results with TTL (5 min), limit concurrent scans per user (max 3), use context cancellation on timeout |
| T-06-06 | Denial of Service | Large PPT processing | mitigate | Limit duplicate detection to first 100 slides, return 413 if larger, enforce via Phase 3 200-slide limit |
| T-06-07 | Escalation of Privilege | PPT ownership check | mitigate | Use middleware.GetUserID pattern from Phase 3, cross-reference PPTFile.SourceVideoFileID ownership |
| T-06-08 | Tampering | Backup file manipulation | mitigate | Store backup path in DB (not client input), validate backup path is within allowed directory before restore |
</threat_model>
