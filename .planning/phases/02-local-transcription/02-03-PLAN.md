2. **Create `internal/services/transcription_service.go`** following SplittingService pattern exactly:

   **Struct `TranscriptionService`**:
   ```
   db               *gorm.DB
   logger           *zap.Logger
   config           *config.Config
   taskQueue        chan *TranscriptionTask
   workers          int            // 1 worker (conservative for memory-intensive transcription)
   cancelFuncs      map[uint]context.CancelFunc
   mu               sync.RWMutex
   wg               sync.WaitGroup
   ctx              context.Context
   cancel           context.CancelFunc
   frameExtractor   *FrameExtractor
   similarityDetector *SimilarityDetector
   pptxGenerator    *PPTXGenerator
   videoFileService *VideoFileService
   statusMap        map[uint]*TranscriptionProgress  // videoFileID -> progress
   statusMu         sync.RWMutex
   ```

   **Struct `TranscriptionProgress`** per D-17:
   ```
   Status          string  // pending, processing, completed, failed
   CurrentStage    string  // extracting, detecting, generating
   FramesProcessed int
   TotalFrames     int
   Percentage      int
   ErrorMessage    string
   ResultPPTFileID *uint
   ```

   **Constructor `NewTranscriptionService`**: Takes db, logger, config, frameExtractor, similarityDetector, pptxGenerator, videoFileService. Initialize taskQueue with capacity 100. Read ffmpegPath from config.

   **Method `Start() error`**: Launch 1 worker goroutine. Same pattern as SplittingService.

   **Method `Stop()`**: Cancel context, wait for WaitGroup. Same pattern as SplittingService.

   **Method `SubmitTranscription(videoFileID uint, samplingRate float64, createdBy uint) error`**:
   - Validate videoFileID exists in database
   - Validate samplingRate is one of [1.0, 0.5, 0.2] (i.e., 1s/2s/5s intervals per D-02)
   - Create TranscriptionTask record in DB with status "pending"
   - Initialize statusMap[videoFileID] with TranscriptionProgress{Status: "processing"}
   - Push task to taskQueue (return error if queue full)

   **Method `GetTranscriptionStatus(videoFileID uint) *TranscriptionProgress`**:
   - Read from statusMap with RLock
   - Return copy of progress (not pointer to shared data)

   **Worker method `worker(id int)`**: Same select pattern as SplittingService.

   **Method `processTranscription(task *TranscriptionTask)`** — the core pipeline:

   a. **Setup**:
      - Create temp dir via `frameExtractor.CreateTempDir(config.Storage.RecordingsPath, task.VideoFileID)`
      - `defer frameExtractor.CleanupTempDir(tempDir)` per D-05
      - Create cancellable context: `ctx, cancel := context.WithTimeout(s.ctx, 10*time.Minute)`
      - `defer cancel()`

   b. **Stage 1: Frame Extraction** per D-01:
      - Update status: stage="extracting"
      - Get video file path from database
      - samplingRateSeconds := 1.0 / task.SamplingRate (convert fps to seconds-per-frame)
      - Call `frameExtractor.ExtractFrames(ctx, videoPath, tempDir, samplingRateSeconds)`
      - Update status: totalFrames = len(frames)
      - Save TranscriptionTask.TotalFrames to DB

   c. **Stage 2: Similarity Detection** per D-01, D-07:
      - Update status: stage="detecting"
      - Keep first frame always (reference frame)
      - For each subsequent frame (i from 1 to len(frames)-1):
        - Decode previous frame and current frame using `jpeg.Decode`
        - Call `similarityDetector.IsFrameChanged(prevImg, currImg)`
        - If Changed, add frame to uniqueFrames list
        - Update status: framesProcessed = i+1, percentage = (i+1)*100/totalFrames
      - Log summary: "Detected N unique frames out of M total frames"

   d. **Stage 3: PPTX Generation** per D-04, D-09:
      - Update status: stage="generating"
      - Re-extract unique frames at original resolution per D-04:
        - For each unique frame, call `frameExtractor.ExtractFrameAtTimestamp(ctx, videoPath, timestamp, highResOutputPath)`
        - Store high-res paths in a slice
      - Generate PPTX: `pptxGenerator.GeneratePPTX(ctx, highResFramePaths, pptxOutputPath)`
      - pptxOutputPath = `filepath.Join(filepath.Dir(videoPath), "transcription_{videoFileID}_{timestamp}.pptx")`

   e. **Completion**:
      - Get file info: size, page count
      - Create PPTFile record in DB:
        ```
        FileName: fmt.Sprintf("%s_转录.pptx", strings.TrimSuffix(sourceFile.FileName, filepath.Ext(sourceFile.FileName)))
        FilePath: pptxOutputPath
        FileSize: fileSize
        PageCount: pageCount
        Format: "pptx"
        SourceVideoFileID: &task.VideoFileID
        TranscriptionTaskID: &task.ID
        ```
      - Update TranscriptionTask: status="completed", ResultPPTFileID=pptFile.ID, Percentage=100
      - Update statusMap: completed with ResultPPTFileID

   f. **Error handling** (wrap entire processTranscription in defer/recover):
      - On any error: Update TranscriptionTask status="failed", ErrorMessage=err.Error()
      - Update statusMap: failed with error message
      - Temp dir cleanup happens via defer regardless

3. **Helper method `updateProgress(videoFileID, stage, processed, total, percentage)`**:
   - Helper to update statusMap with progress data
   - Also update TranscriptionTask record in DB for persistence across restarts

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> API | Untrusted input: video ID, sampling rate — must validate |
| Handler -> Service | Handler validates ownership before delegating to service |
| Service -> Database | Service writes transcription tasks and PPT file records |
| Service -> FFmpeg | Frame extraction via external command — path injection risk |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-07 | Tampering | TranscriptionHandler | mitigate | Validate sampling_rate is one of [1.0, 0.5, 0.2] — whitelist only per D-02 |
| T-02-08 | Spoofing | TranscriptionHandler | mitigate | Verify video file ownership via middleware.GetUserID + admin check before transcription (same pattern as SplitHandler) |
| T-02-09 | Denial of Service | TranscriptionService | mitigate | Worker pool size = 1 (conservative), task queue cap = 100, context timeout = 10 min |
| T-02-10 | Information Disclosure | TranscriptionHandler | mitigate | Return generic error messages to client, log detailed errors server-side only |
| T-02-11 | Denial of Service | TranscriptionService | mitigate | Temp dir cleanup with defer ensures disk space recovery even on panic |
</threat_model>
