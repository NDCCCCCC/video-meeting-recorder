Create `frontend/src/hooks/useSubtitleSync.ts` following the project's established hook pattern (see useKeyboardShortcuts.ts).

**Imports:**
```typescript
import { useState, useEffect, useCallback, useMemo } from 'react'
import type { SubtitleCue } from '../types/subtitle'
```

**Interface:**
```typescript
interface UseSubtitleSyncProps {
  videoRef: React.RefObject<HTMLVideoElement | null>
  vttContent: string | null    // raw WebVTT text content
  enabled: boolean             // whether subtitle sync should be active
}
```

**Return type:** `SubtitleCue | null` (the currently active cue)

**Implementation steps:**

1. **parseWebVTT function** (defined OUTSIDE the hook, at module level):
   - Accept `vttContent: string`, return `SubtitleCue[]`
   - Skip the "WEBVTT" header line and any blank lines after it
   - Split content by blank lines to isolate each cue block
   - For each cue block:
     - Find the line containing `-->` (the timestamp line)
     - Parse start time: split by `-->`, take left part, call `parseTimestamp()`
     - Parse end time: split by `-->`, take right part, call `parseTimestamp()`
     - All remaining lines after the timestamp line are the subtitle text (join with newline)
   - Return array of SubtitleCue objects sorted by startTime
   - Skip malformed blocks (no `-->` found, unparseable timestamps)

2. **parseTimestamp function** (module-level helper):
   - Accept timestamp string like `"00:01:23.456"` or `"01:23.456"` or `"00:01:23.456 "` (may have trailing whitespace)
   - Handle formats: `HH:MM:SS.mmm`, `MM:SS.mmm`, `HH:MM:SS`
   - Convert to total seconds (number)
   - Return 0 if parsing fails

3. **Hook body:**
   - State: `const [currentCue, setCurrentCue] = useState<SubtitleCue | null>(null)`
   - Memoized cues: `const cues = useMemo(() => vttContent ? parseWebVTT(vttContent) : [], [vttContent])`
   - `findActiveCue` callback: binary search or simple find through cues array for `currentTime >= cue.startTime && currentTime <= cue.endTime`
   - `useEffect` that:
     - Guards: if `!enabled || !videoRef.current` return early
     - Gets video element from ref
     - Defines `handleTimeUpdate` that calls `findActiveCue(video.currentTime)` and updates `currentCue` state
     - Adds event listener: `video.addEventListener('timeupdate', handleTimeUpdate)`
     - Returns cleanup: `video.removeEventListener('timeupdate', handleTimeUpdate)`
     - Dependencies: `[enabled, videoRef, cues]`

4. **Return:** `currentCue`

**Critical pitfalls to avoid (from RESEARCH.md):**
- Always return cleanup function from useEffect to prevent memory leaks (Pitfall 5)
- Use `video.timeupdate` event, NOT setTimeout/setInterval (Pitfall 1)
- Handle edge case: video seeking should update subtitle on next timeupdate (browser handles this)

**Note on hex-to-RGB conversion for background opacity:**
```typescript
function hexToRgb(hex: string): { r: number; g: number; b: number } {
  const result = /^#?([a-f\d]{2})([a-f\d]{2})([a-f\d]{2})$/i.exec(hex)
  return result
    ? { r: parseInt(result[1], 16), g: parseInt(result[2], 16), b: parseInt(result[3], 16) }
    : { r: 0, g: 0, b: 0 }
}
```
