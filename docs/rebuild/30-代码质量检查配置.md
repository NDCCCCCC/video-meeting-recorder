# 代码质量检查配置

## 一、概述

### 1.1 目标

建立完整的代码质量检查体系，确保代码：
- 符合Go语言规范
- 无潜在安全和性能问题
- 保持一致的代码风格
- 满足测试覆盖率要求

### 1.2 工具链

| 工具 | 用途 | 配置文件 |
|------|------|----------|
| golangci-lint | 综合代码检查 | .golangci.yml |
| staticcheck | 静态分析 | 集成在golangci-lint |
| gosec | 安全检查 | 集成在golangci-lint |
| go vet | 官方静态检查 | 内置 |
| goimports | 导入排序 | 配置在golangci-lint |
| gocyclo | 圈复杂度 | 配置在golangci-lint |

## 二、golangci-lint配置

### 2.1 完整配置文件

```yaml
# .golangci.yml
run:
  # 运行超时时间
  timeout: 5m

  # 并发数
  concurrency: 4

  # 要检查的Go版本
  go: "1.21"

  # 跳过的目录
  skip-dirs:
    - vendor
    - third_party
    - testdata
    - examples
    - Godeps
    - builtin

  # 跳过的文件
  skip-files:
    - ".*\\.pb\\.go$"
    - ".*\\.gen\\.go$"

  # 构建标签
  build-tags:
    - integration

output:
  # 输出格式：colored-line-number|json|tab|checkstyle|code-climate
  formats:
    - format: colored-line-number
  # 打印检查的linter名称
  print-linter-name: true
  # 排序结果
  sort-results: true

linters:
  # 启用的linter
  enable:
    # 默认启用的linter
    - errcheck          # 检查未处理的错误
    - gosimple          # 简化代码
    - govet             # go vet
    - ineffassign       # 检查无效的赋值
    - staticcheck       # 静态分析
    - typecheck         # 类型检查
    - unused            # 检查未使用的代码

    # 附加linter
    - gofmt             # 代码格式化
    - goimports         # 导入排序
    - misspell          # 拼写检查
    - gocyclo           # 圈复杂度
    - gosec             # 安全检查
    - revive            # 代码风格检查
    - stylecheck        # 样式检查
    - unconvert         # 检查不必要的类型转换
    - unparam           # 检查未使用的参数
    - nakedret          # 检查裸返回
    - prealloc          # 检查预分配
    - exportloopref    # 检查循环变量引用
    - noctx             # 检查缺少context的HTTP请求

    # 性能相关
    - prealloc          # 预分配slice/map
    - bodyclose         # 检查HTTP响应体是否关闭

    # 错误处理
    - errorlint         # 检查错误处理
    - goerr113          # 检查错误包装

    # 代码质量
    - dupl              # 重复代码检查
    - goconst           # 检查可以成为常量的字符串
    - gocritic          # 代码质量检查
    - godot             # 注释风格检查
    - nolintlint        # 检查nolint注释的使用
    - whitespace        # 检查空白字符

  # 禁用的linter及原因
  disable:
    - exhaustivestruct  # 过于严格
    - exhaustiveshift   # 过于严格
    - funlen            # 函数长度限制已由gocyclo处理
    - lll               # 行长度限制
    - wsl               # 空行规则与团队习惯不同

linters-settings:
  # 圈复杂度设置
  gocyclo:
    min-complexity: 15

  # 安全检查设置
  gosec:
    excludes:
      - G104  # 检查未检查的错误，与errcheck重复
      - G307  # defer文件关闭，已有的bodyclose已处理

  # 拼写检查设置
  misspell:
    locale: US
    ignore-words:
      - someword

  # revive设置
  revive:
    confidence: 0.8
    rules:
      - name: blank-imports
      - name: context-as-argument
      - name: context-keys-type
      - name: dot-imports
      - name: error-return
      - name: error-strings
      - name: error-naming
      - name: exported
      - name: if-return
      - name: increment-decrement
      - name: var-naming
      - name: var-declaration
      - name: package-comments
      - name: range
      - name: receiver-naming
      - name: time-naming
      - name: unexported-return
      - name: indent-error-flow
      - name: errorf
      - name: empty-block
      - name: superfluous-else
      - name: unused-parameter
      - name: unreachable-code
      - name: redefines-builtin-id

  # goconst设置
  goconst:
    min-len: 2
    min-occurrences: 3
    ignore-tests: true

  # dupl设置
  dupl:
    threshold: 100

  # gofmt设置
  gofmt:
    simplify: true

  # goimports设置
  goimports:
    local-prefixes: github.com/yourusername/record_go

  # prealloc设置
  prealloc:
    simple: true
    range-loops: true
    for-loops: false

  # bodyclose设置
  bodyclose:
    # 检查HTTP响应体是否关闭
    http-client-always-closes: true

issues:
  # 显示所有问题
  max-issues-per-linter: 0
  max-same-issues: 0

  # 要排除的规则
  exclude-rules:
    # 测试文件中的某些规则可以放宽
    - path: _test\.go
      linters:
        - gocyclo
        - errcheck
        - dupl
        - gosec
        - goconst

    # main函数中可以忽略某些规则
    - path: cmd/
      linters:
        - gochecknoglobals

    # 生成的代码可以忽略
    - path: ".*\\.pb\\.go"
      linters:
        - all

  # 独立排除的问题
  exclude:
    # G108: Profiling endpoint is exposed - 某些情况下需要暴露
    - "G108"

    # errcheck: 某些情况下可以忽略错误
    - "Error return value of .((os\\.)?std)?\\.(Write|Read|Close|Flush) is not checked"

    # staticcheck: 某些SA问题可以忽略
    - "SA9003:"  # empty branch

  # 只显示新问题（用于CI）
  new: false

  # 显示修复建议
  fix: true
```

### 2.2 快速配置

```yaml
# .golangci.yml (精简版)
run:
  timeout: 5m
  go: "1.21"

linters:
  enable:
    - errcheck
    - gosimple
    - govet
    - ineffassign
    - staticcheck
    - typecheck
    - unused
    - gofmt
    - goimports
    - misspell
    - gocyclo
    - gosec

linters-settings:
  gocyclo:
    min-complexity: 15

  gosec:
    excludes:
      - G104

issues:
  exclude-use-default: false
```

## 三、Makefile集成

```makefile
# Makefile
.PHONY: lint lint-fix test test-coverage fmt vet

# 运行linter
lint:
	golangci-lint run --config .golangci.yml ./...

# 自动修复问题
lint-fix:
	golangci-lint run --fix --config .golang-ci.yml ./...

# 格式化代码
fmt:
	go fmt ./...
	goimports -w .

# 代码检查
vet:
	go vet ./...

# 运行测试
test:
	go test -v -race -coverprofile=coverage.out ./...

# 测试覆盖率
test-coverage:
	go test -v -race -coverprofile=coverage.out ./...
	go tool cover -html=coverage.out -o coverage.html

# 完整检查
check: fmt vet lint test

# 快速检查（CI用）
ci-check:
	golangci-lint run --config .golangci.yml --new-from-rev=origin/main ./...
	go test ./...
```

## 五、GitHub Actions集成

```yaml
# .github/workflows/lint.yml
name: Lint

on:
  push:
    branches: [ main, develop ]
  pull_request:
    branches: [ main, develop ]

jobs:
  golangci-lint:
    name: golangci-lint
    runs-on: ubuntu-latest

    steps:
      - uses: actions/checkout@v3

      - name: Set up Go
        uses: actions/setup-go@v4
        with:
          go-version: '1.21'

      - name: golangci-lint
        uses: golangci/golangci-lint-action@v3
        with:
          version: latest
          config: .golangci.yml
          args: --timeout=5m

      - name: Run tests
        run: go test -v -race -coverprofile=coverage.out ./...

      - name: Upload coverage
        uses: codecov/codecov-action@v3
        with:
          files: ./coverage.out
          flags: unittests
```

## 六、Pre-commit钩子

```bash
#!/bin/bash
# .git/hooks/pre-commit

echo "Running golangci-lint..."
golangci-lint run --config .golangci.yml ./...
if [ $? -ne 0 ]; then
    echo "golangci-lint failed, please fix the issues before committing"
    exit 1
fi

echo "Running tests..."
go test ./...
if [ $? -ne 0 ]; then
    echo "Tests failed, please fix the failing tests before committing"
    exit 1
fi

echo "Pre-commit checks passed!"
```

使用pre-commit工具：

```yaml
# .pre-commit-config.yaml
repos:
  - repo: local
    hooks:
      - id: golangci-lint
        name: golangci-lint
        entry: golangci-lint run --config .golangci.yml --fix
        language: system
        pass_filenames: false
      - id: go-fmt
        name: go fmt
        entry: gofmt -w
        language: system
      - id: go-imports
        name: go imports
        entry: goimports -w
        language: system
      - id: go-test
        name: go test
        entry: go test
        language: system
        pass_filenames: false
```

## 七、代码规范文档

### 7.1 命名规范

```go
// ✅ 好的命名
type UserService struct {}
func (s *UserService) CreateUser() {}
const MaxRetries = 3
var globalConfig *Config

// ❌ 不好的命名
type US struct {}
func (s *US) create() {}
const MAX = 3
var cfg *Config
```

### 7.2 错误处理规范

```go
// ✅ 好的错误处理
func process() error {
    result, err := doSomething()
    if err != nil {
        return fmt.Errorf("处理失败: %w", err)
    }
    return nil
}

// ❌ 不好的错误处理
func process() error {
    result, err := doSomething()
    if err != nil {
        return err // 没有上下文信息
    }
    return nil
}
```

### 7.3 注释规范

```go
// ✅ 好的注释
// UserService 提供用户相关的业务逻辑
// 它负责用户的创建、更新、删除和查询操作
type UserService struct {
    db *gorm.DB
}

// CreateUser 创建一个新用户
// 如果用户名已存在，返回 ErrUserExists 错误
func (s *UserService) CreateUser(req *CreateUserRequest) (*User, error) {
    // 实现...
}

// ❌ 不好的注释
// 用户服务
type UserService struct {}

// 创建
func (s *UserService) CreateUser() {}
```

### 7.4 Context使用规范

```go
// ✅ 好的做法
func (s *UserService) CreateUser(ctx context.Context, req *CreateUserRequest) (*User, error) {
    // 所有外部调用都传递context
    return s.repo.Create(ctx, user)
}

// ❌ 不好的做法
func (s *UserService) CreateUser(req *CreateUserRequest) (*User, error) {
    // 缺少context参数
    return s.repo.Create(user)
}
```

## 八、测试覆盖率要求

```yaml
# .golangci.yml 中添加
linters:
  enable:
    # ...其他linter
    - gocyclo

issues:
  exclude-rules:
    # 测试代码可以放宽要求
    - path: _test\.go
      linters:
        - gocyclo
        - errcheck
```

覆盖率目标：

| 组件 | 目标覆盖率 | 说明 |
|------|-----------|------|
| 业务逻辑层 | ≥85% | 核心业务逻辑必须充分测试 |
| 数据层 | ≥80% | 数据库操作需要测试 |
| Handler层 | ≥70% | HTTP处理层测试 |
| 工具函数 | ≥90% | 工具函数要求高覆盖率 |
| 总体覆盖率 | ≥80% | 整体覆盖率目标 |
