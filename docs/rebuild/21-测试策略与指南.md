# 测试策略与指南

## 概述

本文档定义了项目的全面测试策略，包括单元测试、集成测试、端到端测试、性能测试等各个层面的测试方法和最佳实践。

## 测试金字塔

```
        ┌─────────────┐
        │   E2E测试    │  少量，关键业务流程
        │   (10%)    │
       ───────────────
       ───────────────
      ╱                ╲
     ╱  集成测试(30%)   ╱  中等数量，服务间交互
    ╱                  ╱

   ───────────────────
  ╱    单元测试(60%)    ╲  大量，快速反馈
 ╱                      ╱
```

## 测试分层

### 1. 单元测试 (Unit Tests)

测试单个函数或方法的正确性，不依赖外部系统。

**文件结构**:
```
internal/
├── services/
│   ├── user_service.go
│   └── user_service_test.go
├── handlers/
│   ├── user_handler.go
│   └── user_handler_test.go
└── models/
    ├── user.go
    └── user_test.go
```

**原则**:
- 快速执行 (< 0.1秒/测试)
- 无外部依赖（数据库、API、文件系统）
- 可重复执行
- 覆盖率目标: >= 80%

### 2. 集成测试 (Integration Tests)

测试多个组件协同工作的正确性，可能涉及真实数据库。

**文件结构**:
```
tests/
├── integration/
│   ├── api/
│   │   ├── auth_test.go
│   │   ├── user_test.go
│   │   └── conference_test.go
│   ├── service/
│   │   ├── video_recording_test.go
│   │   └── huawei_integration_test.go
│   └── database/
│       └── repository_test.go
├── testdata/
│   └── fixtures/
└── mocks/
    └── mock_server.go
```

**原则**:
- 使用测试数据库
- 使用测试配置
- 独立可执行
- 清理测试数据

### 3. 端到端测试 (E2E Tests)

测试完整的用户场景，从HTTP请求到数据库存储。

**文件结构**:
```
tests/
├── e2e/
│   ├── scenarios/
│   │   ├── conference_lifecycle_test.go
│   │   ├── user_authentication_test.go
│   │   └── recording_workflow_test.go
│   └── support/
│       └── test_utils.go
```

### 4. 性能测试 (Benchmark Tests)

测试代码性能，识别瓶颈。

**文件结构**:
```
internal/
├── services/
│   ├── video_recording_service.go
│   └── video_recording_bench_test.go
└── common/
    ├── validator.go
    └── validator_bench_test.go
```

```go
package services

import (

// TestUserService_CreateUser 测试创建用户
func TestUserService_CreateUser(t *testing.T) {
    // 准备测试数据和依赖
    logger := zap.NewNop()
    mockRepo := new(MockUserRepository)
    service := NewUserService(logger, mockRepo)

    tests := []struct {
        name    string
        input   *CreateUserRequest
        mockFn  func()
        wantErr bool
        errMsg  string
    }{
        {
            name: "成功创建用户",
            input: &CreateUserRequest{
                Username: "testuser",
                Email:    "test@example.com",
                Password: "Test@123",
            },
            mockFn: func() {
                mockRepo.On("Create", mock.Anything, mock.AnythingOfType("*models.User")).
                    Return(uint(1), nil).
                    Once()
            },
            wantErr: false,
        },
        {
            name: "用户名已存在",
            input: &CreateUserRequest{
                Username: "existinguser",
                Email:    "new@example.com",
                Password: "Test@123",
            },
            mockFn: func() {
                mockRepo.On("GetByUsername", mock.Anything, "existinguser").
                    Return(&models.User{ID: 1}, nil).
                    Once()
            },
            wantErr: true,
            errMsg:  "用户名已存在",
        },
        {
            name: "邮箱格式错误",
            input: &CreateUserRequest{
                Username: "testuser",
                Email:    "invalid-email",
                Password: "Test@123",
            },
            mockFn:  func() {}, // 不调用mock
            wantErr: true,
            errMsg:  "邮箱格式错误",
        },
    }

    for _, tt := range tests {
        t.Run(tt.name, func(t *testing.T) {
            // 设置Mock期望
            tt.mockFn()

            // 执行测试
            user, err := service.CreateUser(context.Background(), tt.input)

            // 验证结果
            if tt.wantErr {
                assert.Error(t, err)
                if tt.errMsg != "" {
                    assert.Contains(t, err.Error(), tt.errMsg)
                }
                assert.Nil(t, user)
            } else {
                assert.NoError(t, err)
                assert.NotNil(t, user)
                assert.Equal(t, tt.input.Username, user.Username)
                assert.Equal(t, tt.input.Email, user.Email)
            }

            // 验证所有Mock期望都被调用
            mockRepo.AssertExpectations(t)
        })
    }
}
```

```go
func TestConcurrentRecording(t *testing.T) {
    service := NewVideoRecordingService(logger)

    // 模拟并发启动多个录制任务
    concurrency := 10
    done := make(chan bool, concurrency)

    for i := 0; i < concurrency; i++ {

            err := service.StartRecording(context.Background(), req)
```

```go
package e2e

import (
    "context"
    "testing"
    "time"

    "github.com/stretchr/testify/assert"
    "github.com/stretchr/testify/require"
    "myproject/internal/models"
)

// TestConferenceLifecycle 测试完整的会议生命周期
func TestConferenceLifecycle(t *testing.T) {
    // 1. 创建测试服务器
    ts, cleanup := setupTestServer(t)
    defer cleanup()

    // 2. 创建用户并登录
    token := createAndLoginUser(t, ts)

    // 3. 创建会议
    conference := createConference(t, ts, token, &ConferenceRequest{
        Name:      "E2E测试会议",
        StartTime: time.Now().Add(time.Hour),
        EndTime:   time.Now().Add(2 * time.Hour),
    })

    // 4. 启动会议
    startConference(t, ts, token, conference.ID)
    assert.Equal(t, models.StatusRunning, getConference(t, ts, token, conference.ID).Status)

    // 5. 开始录制
    recording := startRecording(t, ts, token, conference.ID)
    assert.NotNil(t, recording)

    // 6. 等待录制进行
    time.Sleep(5 * time.Second)
    recording = getRecording(t, ts, token, recording.ID)
    assert.Equal(t, models.RecordingStatusRecording, recording.Status)

    // 7. 停止录制
    stopRecording(t, ts, token, recording.ID)
    recording = getRecording(t, ts, token, recording.ID)
    assert.Equal(t, models.RecordingStatusCompleted, recording.Status)

    // 8. 停止会议
    stopConference(t, ts, token, conference.ID)
    conference = getConference(t, ts, token, conference.ID)
    assert.Equal(t, models.StatusStopped, conference.Status)

    // 9. 验证文件生成
    files := getConferenceFiles(t, ts, token, conference.ID)
    assert.NotEmpty(t, files)
}

// TestRecordingWorkflow 测试录制工作流
func TestRecordingWorkflow(t *testing.T) {
    ts, cleanup := setupTestServer(t)
    defer cleanup()

    token := createAndLoginUser(t, ts)

    // 1. 创建并启动会议
    conference := createAndStartConference(t, ts, token)

    // 2. 添加多个RTSP流
    streams := []string{
        "rtsp://example.com/stream1",
        "rtsp://example.com/stream2",
    }

    for _, streamURL := range streams {
        addStream(t, ts, token, conference.ID, streamURL)
    }

    // 3. 启动多流录制
    recording := startMultiStreamRecording(t, ts, token, conference.ID)

    // 4. 监控录制状态
    ctx, cancel := context.WithTimeout(context.Background(), 30*time.Second)
    defer cancel()

    for {
        select {
        case <-ctx.Done():
            t.Fatal("录制超时")
        default:
            recording = getRecording(t, ts, token, recording.ID)
            if recording.Status == models.RecordingStatusRecording {
                // 录制成功启动
                return
            }
            if recording.Status == models.RecordingStatusFailed {
                t.Fatalf("录制失败: %v", recording.Error)
            }
            time.Sleep(time.Second)
        }
    }
}
```

```go
func WaitForCondition(t *testing.T, condition func() bool, timeout time.Duration, checkInterval time.Duration) {
    ctx, cancel := context.WithTimeout(context.Background(), timeout)
    defer cancel()

    ticker := time.NewTicker(checkInterval)
    defer ticker.Stop()

    for {
        select {
        case <-ctx.Done():
            t.Fatal("等待条件超时")
        case <-ticker.C:
            if condition() {
                return
            }
        }
    }
}
```

## 最佳实践

### 1. 测试命名

```go
// ✅ 好的命名
func TestUserService_CreateUser_Success(t *testing.T)
func TestUserService_CreateUser_DuplicateUsername_ReturnsError(t *testing.T)
func TestConference_Start_WhenAlreadyRunning_ReturnsError(t *testing.T)

// ❌ 不好的命名
func TestUser1(t *testing.T)
func TestCreate(t *testing.T)
func TestError(t *testing.T)
```

### 2. AAA模式

```go
func TestSomething(t *testing.T) {
    // Arrange - 准备测试数据和环境
    service := NewService()
    input := "test"

    // Act - 执行被测试的操作
    result, err := service.DoSomething(input)

    // Assert - 验证结果
    assert.NoError(t, err)
    assert.Equal(t, "expected", result)
}
```

### 3. 测试隔离

```go
// ✅ 每个测试独立
func TestA(t *testing.T) {
    db := setupTestDB(t)
    defer cleanup(db)
    // 测试逻辑...
}

func TestB(t *testing.T) {
    db := setupTestDB(t)
    defer cleanup(db)
    // 测试逻辑...
}

// ❌ 测试间有依赖
var globalDB *gorm.DB

func TestA(t *testing.T) {
    globalDB = setupTestDB(t)
}

func TestB(t *testing.T) {
    // 依赖TestA设置的globalDB
}
```

### 4. 使用Table-Driven Tests

```go
// ✅ 推荐：表驱动测试
tests := []struct {
    name     string
    input    string
    expected string
    wantErr  bool
}{
    {"case1", "input1", "output1", false},
    {"case2", "input2", "output2", true},
}

for _, tt := range tests {
    t.Run(tt.name, func(t *testing.T) {
        // 测试逻辑
    })
}

// ❌ 不推荐：重复的测试代码
func TestCase1(t *testing.T) { /* ... */ }
func TestCase2(t *testing.T) { /* ... */ }
```

### 5. Mock使用原则

```go
// ✅ 使用Mock测试业务逻辑
func TestUserService(t *testing.T) {
    mockRepo := new(MockRepository)
    service := NewService(mockRepo)

    mockRepo.On("Get", 1).Return(expected, nil)
    // 测试Service逻辑
}

// ❌ 不要Mock被测试的对象
func TestRepository(t *testing.T) {
    // 不应该Mock数据库，应该使用测试数据库
}
```

### 6. 测试数据管理

```go
// ✅ 使用测试fixture
func TestWithFixture(t *testing.T) {
    fixture := LoadUserFixture(db)
    user := fixture.RegularUser
    // 测试逻辑

// ❌ 在每个测试中硬编码数据
func TestHardcoded(t *testing.T) {
    user := &User{
        Username: "test",
        Email:    "test@example.com",
        // ...很多字段
    }

```

### 7. 避免测试中的Sleep

```go
// ❌ 使用Sleep等待
func TestBad(t *testing.T) {
    service.Start()
    time.Sleep(5 * time.Second) // 不可靠
    assert.True(t, service.IsRunning())
}

// ✅ 使用条件等待
func TestGood(t *testing.T) {
    service.Start()
    assert.Eventually(t, func() bool {
        return service.IsRunning()
    }, 5*time.Second, 100*time.Millisecond)
}
```
