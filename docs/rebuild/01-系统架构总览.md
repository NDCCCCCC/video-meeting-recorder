# 视频会议录制管理系统 - 系统架构总览

## 一、系统概述

### 1.1 项目简介

视频会议录制管理系统是一个基于Go语言构建的企业级解决方案，与华为视频会议系统深度集成，提供自动化会议录制功能。系统采用**六边形架构**（Hexagonal Architecture）设计，通过**统一接口模式**实现了清晰的关注点分离。

### 1.2 核心功能

| 功能模块 | 说明 |
|---------|------|
| **会议管理** | 创建、查询、更新、删除会议记录 |
| **任务调度** | 基于Cron的定时录制任务调度 |
| **视频录制** | FFmpeg驱动的多格式视频录制 |
| **直播推流** | RTSP流媒体处理和分发 |
| **设备管理** | 华为终端设备的连接和控制 |
| **文件管理** | 视频文件的存储、转换和下载 |
| **用户认证** | 基于JWT的用户认证和授权 |

### 1.3 技术栈

```yaml

```

## 三、核心组件

### 3.1 应用程序生命周期管理

**`cmd/server/app.go`** 中的 `MinimalApp` 结构管理应用程序的完整生命周期：

```go
type MinimalApp struct {
    config      *config.Config
    logger      *zap.Logger
    db          *gorm.DB
    services    map[string]common.Service
    httpServer  *gin.Engine
}

// 生命周期阶段
func (a *MinimalApp) Initialize() error
func (a *MinimalApp) Start() error
func (a *MinimalApp) Stop() error
```

**启动流程**：

```
1. 环境准备
   ├── 配置文件加载
   ├── 日志初始化
   └── 端口检测(8080 → 8081备用)

2. 应用创建
   ├── 数据库连接
   ├── 数据库迁移
   └── 服务实例化

3. 服务配置
   ├── 核心服务注册
   ├── 视频录制服务注册
   └── 华为集成服务注册

4. 应用启动
   ├── HTTP服务器启动
   ├── 信号处理注册
   └── 优雅关闭等待
```

### 4.2 数据库连接配置

```yaml
# config.yaml
database:
  # SQLite数据库配置（纯Go驱动，无需CGO）
  driver: sqlite
  path: ./data/record.db              # 数据库文件路径
  enable_wal: true                   # 启用WAL模式（提高并发性能）
  enable_foreign_key: true           # 启用外键约束
  journal_mode: WAL                  # 日志模式
  synchronous: NORMAL                 # 同步模式（性能平衡）
  cache_size: 2000                   # 缓存大小（页）
  busy_timeout: 5000                  # 忙略超时（毫秒）

  # SQLite连接池配置（注意：SQLite单连接限制）
  max_open_conns: 1                   # 最大打开连接数
  max_idle_conns: 1                   # 最大空闲连接数
  conn_max_lifetime: 0                # 连接最大生命周期（0=无限）
```

## 八、架构优势与挑战

### 8.1 优势

| 优势 | 说明 |
|-----|------|
| **关注点分离** | 六边形架构清晰分离业务逻辑和基础设施 |
| **可测试性** | 通过接口隔离，易于单元测试和集成测试 |
| **可扩展性** | 新功能可以作为新服务添加，不影响现有代码 |
| **统一接口** | 所有服务实现相同接口，便于管理 |
| **跨平台支持** | Windows/Linux/macOS全平台支持 |

### 8.2 挑战与改进方向

| 挑战 | 当前状态 | 改进方向 |
|-----|---------|---------|
| **循环依赖** | 部分组件存在循环依赖 | 使用依赖注入容器 |
| **服务发现** | 硬编码服务引用 | 实现服务注册与发现 |
| **错误处理** | 分散在各处 | 统一错误处理中间件 |
| **测试覆盖** | 部分模块无测试 | 目标80%+覆盖率 |
| **文档完善** | 需要补充API文档 | 自动生成Swagger文档 |
